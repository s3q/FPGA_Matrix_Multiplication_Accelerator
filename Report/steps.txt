# UART Matrix Multiplication using FPGA + HPS Linux Console

Important idea:

```text
FPGA does matrix multiplication
HPS reads results through lightweight HPS-FPGA bridge
Linux C program prints results using UART console
```

So the UART is used by **Linux console**, not directly by FPGA.

---

# 1. Create / open Quartus project

Open:

```text
fpga_matrix_8x8.qpf
```

Set top-level entity:

```text
HPSFPGA
```

---

# 2. Platform Designer / Qsys

Open your Qsys system:

```text
hps_fpga.qsys
```

Keep existing:

```text
HPS
SDRAM
UART
SD Card
USB
Ethernet
SW PIO
LED PIO
```

---

# 3. Add matrix PIOs

Add 5 PIO blocks:

| PIO name        | Direction | Width |
| --------------- | --------: | ----: |
| `matrix_ctrl`   |    Output |    32 |
| `matrix_index`  |    Output |     6 |
| `matrix_status` |     Input |    32 |
| `matrix_data`   |     Input |    32 |
| `matrix_cycles` |     Input |    32 |

Meaning:

```text
matrix_ctrl   → HPS starts FPGA
matrix_index  → HPS selects C[0] to C[63]
matrix_status → FPGA sends busy/done
matrix_data   → FPGA sends selected result
matrix_cycles → FPGA sends cycle count
```

---

# 4. Connect PIOs in Qsys

For every PIO:

```text
clk   → main clock
reset → main reset
s1    → h2f_lw_axi_master
```

Export each PIO external connection.

Then:

```text
System → Assign Base Addresses
```

This prevents overlap errors.

---

# 5. Generate HDL

In Platform Designer:

```text
Generate HDL
```

Choose:

```text
VHDL
```

This updates:

```text
hps_fpga.vhd
hps_fpga.sopcinfo
hps_fpga.qip
```

Do not manually edit generated `hps_fpga.vhd`.

---

# 6. Update top-level `HPSFPGA.vhd`

Your top-level must connect:

```text
hps_fpga PIO ports ↔ matrix_core_pio
```

You already did this.

Make sure `HPSFPGA.vhd` includes:

```vhdl
matrix0 : entity work.matrix_core_pio
```

---

# 7. Add matrix core file

Add this file to Quartus:

```text
matrix_core_pio.vhd
```

Path:

```text
Project → Add/Remove Files in Project → Add
```

Also make sure this is included:

```text
hps_fpga.qip
```

---

# 8. Compile Quartus

Run:

```text
Processing → Start Compilation
```

If successful, program FPGA:

```text
Tools → Programmer → Start
```

---

# 9. Generate `hps_0.h`

Open:

```text
Intel FPGA Embedded Command Shell
```

Go to your project folder:

```bat
cd C:\your\project\folder
```

Run:

```bat
sopc-create-header-files .\hps_fpga.sopcinfo --single hps_0.h --module hps_0
```

This creates/updates:

```text
hps_0.h
```

It must include:

```c
MATRIX_CTRL_BASE
MATRIX_INDEX_BASE
MATRIX_STATUS_BASE
MATRIX_DATA_BASE
MATRIX_CYCLES_BASE
```

---

# 10. Write HPS Linux C program

Create:

```text
matrix.c
```

Use `/dev/mem`, not `termios`.

The program does:

```text
open /dev/mem
mmap lightweight bridge 0xFF200000
write matrix_ctrl start bit
wait until matrix_status done
read C[0] to C[63]
print matrix using printf
print cycle_count
```

---

# 11. Copy files to HPS Linux

Copy to board:

```text
matrix.c
hps_0.h
```

You can use:

```bash
scp matrix.c root@BOARD_IP:/home/root/
scp hps_0.h root@BOARD_IP:/home/root/
```

Or USB flash drive.

---

# 12. Compile on HPS Linux

On the board Linux console:

```bash
gcc matrix.c -o matrix
```

If `gcc` is not installed, you must cross-compile from the Intel embedded shell.

---

# 13. Run on HPS Linux

```bash
sudo ./matrix
```

# Final architecture

```text
A and B matrices stored in FPGA
        ↓
matrix_core_pio.vhd
        ↓
PIO registers
        ↓
HPS lightweight bridge
        ↓
Linux C program
        ↓
printf()
        ↓
UART console / PuTTY
```

This is why the project name can be:

```text
FPGA-Based Matrix Multiplication Accelerator with HPS UART Console Output
```
